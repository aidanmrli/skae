## Key design decisions baked in

- **Sequence length = 10** for the new Dysts training. Set in
  `skae/benchmarks/paper_benchmark_manifest.py:18` as
  `PAPER_BENCHMARK_SEQUENCE_LENGTH = 10`. *Multibasin training is unchanged
  — it uses `TRANSITION_RICH_BASIN_PARTITION_SEQUENCE_LENGTH = 8`. If the
  user wants seq=10 multibasin too, that is a separate re-train.*
- **12 Dysts systems** (drop `Duffing`, `SprottTorus`, `RikitakeDynamo`).
  Set in `tools/build_dysts_long_horizon_eval_tasks.py:DYSTS_SYSTEMS`.
- **5 Dysts recipes** (drop low-sparsity block-diagonal variants):
  | Recipe label | base_variant | sparsity_coeff |
  |---|---|---:|
  | `generic_sparse_ns200k_best` | `generic_sparse` | `0.006` (was `0.0025`) |
  | `generic_sparse_sc0_ns200k_best` | `generic_sparse` | `0.0` (zero-sparsity dense baseline) |
  | `generic_sparse_blockdiag_ns200k_sc6em3` | `generic_sparse_blockdiag` | `0.006` |
  | `lista_blockdiag_ns200k_denseopt_sc6em3` | `lista_blockdiag` | `0.006` |
  | `lista_dense_promoted_stage4` | `lista_dense` | `0.006` (was `0.003`) |

  Note: the labels are kept the same for downstream eval compatibility, but
  the recipes underneath have changed. If you are checking artifacts, the
  recipe spec is in `results/paper_followup_recipes_200k_seq10_seeds0to14_20260428/task_tables/paper_followup_recipes_manifest.json`.
- **15 seeds** for Dysts (was 10), **15 seeds** for multibasin (was 10).
  Both meet the Holm-floor headroom for paired Wilcoxon at the
  per-Holm-batch sizes used in Tables 2-4.
- **New long-horizon Dysts eval grid:** horizons
  `5K, 10K, 20K, 30K, 40K, 50K, 60K`; re-encode periods
  `{50, 75, 100, 200, 400, 600, 1000}`. Done in a single rollout to
  `H=60000` with the periodic re-encode evaluator; MSE is read at each
  horizon. The test split uses the `long60` Dysts cache profile
  (`steps=60000`, `trajectories=200`, `warmup=2000`), so this evaluates
  beyond the 30K training-source trajectory horizon without changing the
  training setup.
- **Cell point estimate for Tables 2/3 will be IQM, not median** (per
  conversation alignment). The current `.tex` still says "median". Update
  when redrafting.

## Known risks / things to double-check next session

- **Long-horizon eval at H=60000** is twice the Dysts training-source
  trajectory horizon and longer than the prior H=30000 campaign. Each
  per-(system, seed) eval job has 6 h walltime (set via
  `EVAL_TIME_LIMIT=06:00:00` in the orchestrator). If any time out, requeue
  with a longer limit. The previous campaign needed a "rescue pass" for
  some systems; expect similar.
- **`dysts_native_cache`**: the long-horizon eval reuses the existing
  `/network/scratch/l/lia/skae/dysts_native_cache`. The `long60` test cache
  is distinct from the 30K `full` cache; if it is not already present, the
  prebuild/validate steps in the queue script will compute it. That step
  takes time but is one-shot.
- **Multibasin → routing eval root-spec merging.** The collect step
  documented above is the trickiest part; verify on one variant before
  running all three. If it cannot natively merge two source paths for the
  same model variant, the symlink workaround mentioned above is the
  fallback.
- **`PAPER_BENCHMARK_SEQUENCE_LENGTH = 10`** also affects any *future*
  paper-benchmark training (Hopfield, Kuramoto sweeps that still use this
  constant). If that becomes a problem, gate the change behind a CLI flag
  in the relevant builders rather than reverting.
- The IQM helper falls back to plain mean when `n < 4`. This matters for
  Table 2 where some per-system seed pairs may be small after filtering.
  Sanity-check the per-cell `n` in the new JSON before splicing into the
  paper.
