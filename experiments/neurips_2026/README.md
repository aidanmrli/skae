# NeurIPS 2026 experiment and evidence workflow

This directory owns every choice that is specific to
`docs/neurips_sparse_koopman_multibasin.tex`. Reusable model and environment
implementation stays in `skae/`; SLURM resource orchestration stays in
`scripts/neurips_2026/`.

There are two reproducibility levels:

1. **Exact paper reproduction from versioned evidence.** This verifies the
   compact evidence-backed result artifacts and all declared paper inputs, then
   builds the PDF. It requires no historical checkpoint directory.
2. **Evidence regeneration from trained runs.** This rebuilds row packets from
   checkpoints or reruns the campaigns. Training outputs are intentionally not
   committed; their reviewed roots and hashes are recorded in the provenance
   files under `docs/figures/neurips_paper_2026/_data/`.

## Exact paper reproduction

From a clean clone, install the locked environment:

```bash
uv sync
```

Obtain a CPU compute allocation before running Python:

```bash
salloc --mem=8G -c 4 --partition=long
```

Inside the allocation, run the single paper check:

```bash
uv run skae-paper protocol validate
uv run skae-paper check
uv run pytest
```

`skae-paper check` verifies the frozen headline rows, independent
high-dimensional displays, controlled per-system tables, Dysts appendix
evidence, standalone controls, staged local-operator table,
coordinate-intervention artifacts, and all 16 benchmark vector-field PDFs.
Builders use `--check` mode and fail if regenerated bytes, declared provenance,
or recorded SHA-256 hashes differ. The umbrella check launches each builder in
a fresh Python process so plotting-library state cannot leak between otherwise
deterministic commands.

Then build the manuscript (LaTeX builds are allowed on the login node):

```bash
latexmk -cd -pdf docs/neurips_sparse_koopman_multibasin.tex
```

The expected output is `docs/neurips_sparse_koopman_multibasin.pdf`. The TeX
source includes only artifacts under `docs/figures/neurips_paper_2026/` and
single-purpose fragments under `docs/appendix/`.

## Artifact traceability

Start from
`docs/figures/neurips_paper_2026/manifest.json`. Each evidence group declares:

- the compact row-level input;
- the canonical generator module and `skae-paper` command;
- the provenance file;
- the exact paper output;
- any aggregation contract or known limitation.

The generation flow is:

```text
frozen protocol + trained runs
            |
            v
collectors / evidence freezers
            |
            v
versioned rows + provenance in _data/
            |
            v
deterministic builders
            |
            v
tables in _tables/ and figures beside them
            |
            v
neurips_sparse_koopman_multibasin.tex -> PDF
```

Do not edit generated tables by hand. Change the compact input or builder,
rebuild, and update the paper claim if warranted.

## Command map

The stable command surface is `uv run skae-paper <group> <operation>`. Use
`uv run skae-paper --help` for the current list.

| Purpose | Command |
|---|---|
| Inspect the frozen roster | `uv run skae-paper protocol show` |
| Validate invariants and declared outputs | `uv run skae-paper protocol validate` |
| Verify all paper evidence | `uv run skae-paper check` |
| Build controlled task table | `uv run skae-paper tasks controlled ...` |
| Build Dysts task table | `uv run skae-paper tasks dysts ...` |
| Build Dysts evaluation tasks | `uv run skae-paper tasks dysts-evaluation ...` |
| Build standalone-control tasks | `uv run skae-paper tasks baselines ...` |
| Collect controlled forecasting | `uv run skae-paper collect controlled ...` |
| Collect Dysts forecasting | `uv run skae-paper collect dysts ...` |
| Reduce/merge support alignment | `uv run skae-paper alignment reduce ...`, then `alignment merge ...` |
| Render headline evidence | `uv run skae-paper build headline` |
| Render forecasting horizon trends | `uv run skae-paper build forecasting-horizons` |
| Render high-dimensional evidence | `uv run skae-paper build high-dimensional` |
| Render controlled appendix | `uv run skae-paper build controlled` |
| Render Dysts appendix | `uv run skae-paper build dysts` |
| Render standalone controls | `uv run skae-paper build baselines` |
| Render local-operator evidence | `uv run skae-paper build local-operators` |
| Render interventions | `uv run skae-paper build interventions` |
| Render benchmark vector fields | `uv run skae-paper build ground-truth --formats pdf` |

Command-specific help is forwarded normally, for example
`uv run skae-paper build controlled --help`.

The old `tools/*.py` names are compatibility shims only. New automation and
documentation must use `skae-paper`, `skae-train`, or `skae-evaluate`.

## Code ownership inside this package

- `protocol.py`: immutable paper roster, seeds, budgets, model-row mapping,
  display labels, standalone-baseline method sets, and reviewed exceptions.
- `controlled.py`: exact controlled benchmark recipes used to construct tasks.
- `alignment.py`: evaluation-only support-family and basin/proxy-label metrics.
- `paths.py`: repository, evidence, results, and scratch path resolution.
- `workflows/`: task construction, checkpoint collection, comparison,
  reevaluation, cache preparation, and alignment reduction.
- `evidence/`: deterministic paper tables, figures, statistics, and evidence
  freezing.
- `baselines/`: classical and local-linear standalone controls.
- `local_operators/`: the paper-specific two-stage routed-operator protocol,
  trainer, artifact schema, and reevaluation; `contract.py` owns static
  scientific settings, `routing.py` applies them to the parameterized library
  mechanics, and `protocol.py` implements selection and artifact validation.
- `interventions/`: coordinate-intervention evaluation, evidence freezing, and
  display construction; `protocol.py` owns the one-checkpoint case-study
  defaults shared by the evaluator, launcher, and frozen evidence validator.

No module here should become a general model dependency. If another experiment
needs the same mechanism, move the reusable mechanism into `skae/` and retain
only the paper settings here.

The dependency within the paper package is deliberately one-way:

```text
protocol/contract modules -> task/workflow modules -> evidence builders -> docs artifacts
```

Shell launchers invoke that chain through the CLI and never define a parallel
scientific contract. Historical checkpoint and variant strings are preserved
as immutable artifact identifiers; maintained Python APIs use descriptive
controlled-benchmark names, with legacy imports isolated in compatibility
shims.

The active vector-field directory is one complete paper artifact set: its
builder accepts only the frozen roster, canonical PDF format, and individual
panels. Use a separate `--output-dir` for exploratory subsets or alternate
formats so a partial command cannot silently replace the paper packet.

## Full campaign regeneration

All GPU work must be submitted through SLURM. The maintained entry points are:

```bash
sbatch scripts/neurips_2026/controlled/queue_training.sh
sbatch scripts/neurips_2026/dysts/queue_training.sh
sbatch scripts/neurips_2026/baselines/queue.sh
sbatch scripts/neurips_2026/local_operators/queue_training.sh
```

Support alignment and interventions are evaluation-only chains:

```bash
bash scripts/neurips_2026/controlled/queue_alignment.sh
sbatch scripts/neurips_2026/interventions/run.sh
```

The queue launchers build task tables before submission and submit dependency
chains for collection/evaluation where applicable. They default to `long` and
resolve storage using `SKAE_SCRATCH_ROOT`, then `SCRATCH`, then the current Mila
user's scratch directory. Override these variables explicitly when moving to a
different cluster:

```bash
export SKAE_SCRATCH_ROOT=/shared/path/skae
export DYSTS_CACHE_DIR=/shared/path/skae/dysts_native_cache
```

For a complete rerun, preserve the generated task TSV, task manifest, Git
commit, environment lock, checkpoint roots, collector arguments, row packet,
and provenance JSON. Only freeze a replacement row packet after confirming the
frozen system/seed roster and inspecting missing or nonfinite cells.

## Frozen scientific contract

- Controlled benchmark: 15 retained systems and 15 seeds.
- Dysts benchmark: 10 retained systems and the same 15 seeds.
- Six neural model rows are mapped across the two benchmark-specific task IDs
  in `PAPER_MODEL_ROWS`.
- Dense no-sparsity uses a tanh encoder and zero sparsity coefficient.
- Training-time methods do not receive a basin count or basin labels.
- Basin metadata is permitted only for benchmark evaluation; any structured
  block-count diagnostic remains explicitly labeled as such.
- Alignment uses absolute support threshold `1e-3`, Jaccard `0.50`, and the
  tie-inclusive high-center-margin evaluation slice.
- The staged routed local operator uses its separately frozen Jaccard `0.40`
  route-family definition.

`uv run skae-paper protocol validate` enforces the programmatic invariants.
Paper prose and protocol interpretation remain owned by the main TeX source and
its included appendix fragments.
